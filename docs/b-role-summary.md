## 2. 원본 해부 — "원본은 무엇을 못 하나"

- 도구: Wappalyzer, 개발자도구 Network 탭 → Next.js + React, 검색 API `api.musinsa.com/api2/dp/v2/plp/goods`
- 검색 파라미터 `keyword · color · category · minPrice/maxPrice · sortCode` = **정확한 단어 + 직접 고르는 필터**
- 실험: `패딩` 33,853건 / `빵빵한 겨울 점퍼` **0건** / `겨울에 입을 깔끔한 검은색 외투` **0건**
- 스타일·계절은 검색 필터에 없고, 스타일은 랭킹 탭에만 있음
- 원본에도 상세 화면 "AI 추천 · 비슷한 상품"이 있지만, 한 번 보여 주고 끝 → 조건을 이어서 바꾸거나 이유를 설명하지 못함

## 3. 챗봇은 어떻게 동작하나 (발표 설명용)

문장 하나가 들어오면 다섯 단계를 거칩니다. 모두 `src/services/`에 있고, `chatEngine.respond(문장, 현재 조건)` 하나로 묶여 있습니다.

| 단계 | 파일 | 하는 일 | 예시 |
|---|---|---|---|
| ① 문장 해석 | `parseQuery.ts` | 동의어 사전(`synonyms.ts`, 약 60개 표현)으로 옷 종류·색·스타일·계절·상황·핏·가격·제외 조건을 뽑는다. 찾은 단어는 문장에서 지워 가며 읽어서 "봄버"의 "봄"을 계절로 오해하지 않음 | "빵빵한 겨울 점퍼" → 패딩 · 겨울 · 경량패딩 제외 |
| ② 조건 누적 | `applyPatch.ts` | 이전 조건 위에 **바뀐 부분만** 덮어쓴다 (`reset → clear → set → add`) | "더 스트릿하게" → 스타일만 추가, 예산·계절은 유지 |
| ③ 거르기 | `searchProducts.ts` | 가격 상한·제외 조건 등 반드시 지켜야 할 조건으로 먼저 거른다 | 15만 원 초과, 패딩 → 제외 |
| ④ 점수·정렬·이유 | `recommendProducts.ts` | 스타일·상황·인기도로 점수를 매겨 정렬하고 추천 이유를 만든다. 0건이면 **조건 완화 버튼**을 만든다 | "겨울용 · 블랙 · 학교룩 · 15만 원 이하" / "색상 조건 빼기 (3개)" |
| ⑤ 응답 생성 | `generateResponse.ts` | 응답 6종(추천·용어 설명·추가 질문·0건·미지원·일반)을 무시니 말투로 | "아우터 · 겨울 · 블랙 … 조건으로 5개를 찾았어요." |

핵심 설계 두 가지
- **조건 패치(ConditionPatch)**: "검은색 **위주로**"는 교체(`set`), "네이비**도**"는 추가(`add`), "가격은 상관없어"는 해제(`clear`), "처음부터"는 초기화(`reset`). 이 구분 덕분에 T03·T04(조건 유지하며 일부만 변경)가 통과.
- **찾기와 빼기의 비대칭**: "패딩"을 찾으면 롱패딩·경량패딩까지 포함, "너무 두껍지 않은"은 패딩·롱패딩만 빼고 경량패딩은 남김.

## 4. 화면 쪽에서 B가 만든 것

- 대화 상태를 앱 전체(`ChatProvider`)에 두어 상품 상세에 갔다 와도 대화·조건이 유지 (T13), `sessionStorage`로 새로고침에도 유지
- 현재 조건 칩(×로 하나씩 지우기), 추천 상품 카드(A의 `ProductCard` 재사용) + 추천 이유, 추천 질문·조건 완화 버튼, 용어 설명 카드
- 모바일: 하단 고정 입력창 16px(iOS 확대 방지), 키보드 높이에 맞춰 화면이 줄어듦(`visualViewport`)
- 진입 3곳: 홈 떠 있는 버튼 `/ai`, 검색 0건 카드 `/ai?q=문장`, 상세 "AI 추천" `/ai?product=id`
- 사진: 샘플 사진 3장만 "분석 결과" 연결, 일반 사진은 미리보기 + 특징 질문 (분석하는 척하지 않음)

## 7. 발표에서 B가 말할 포인트

1. **문제는 해부에서 나왔다**: 원본 검색에 같은 문장을 넣으면 0건 (plan.md 4-3) → 시연 ①
2. **같은 문장을 무시니는 이해한다**: 동의어 사전 + 조건 추출 → 시연 ②·③
3. **대화로 좁혀 간다**: 조건 패치 (바뀐 것만 덮어쓰기) → 시연 ④, 이게 원본 "비슷한 상품"과의 차이
4. **아무거나 보여 주지 않는다**: 0건이면 완화 버튼 → 시연 ⑤
5. **한계도 말한다**: 규칙 기반이라 사전에 없는 표현은 못 알아듣고, 사진은 샘플만. LLM은 비용·일관성 때문에 이번엔 안 씀

| 질문 | 답 |

| 진짜 AI인가? | 규칙 기반(동의어 사전 + 조건 추출). 비용 0, 같은 입력이면 같은 결과, 오프라인 동작 |
